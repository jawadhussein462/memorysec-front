<h3>Website and dashboard for <a href="https://github.com/jawadhussein462/mimvo">mimvo</a>, the security scanner for AI agent memory.</h3>

---

- `/`: landing page. Two calls to action, as on most open-source startups' sites: **Book a demo** (`/demo`) and
  **Try open source** (`/docs`), and the docs lead on to GitHub.
- `/docs`: documentation, ported from the package README. Mimvo is not on PyPI, so every install step uses git and uv.
- `/demo`: demo request form. Submitting it emails `site.contactEmail` (`/api/demo`).
- `/dashboard`: interactive dashboard. It opens on a sample scan, and it opens **your own report**: run
  `mimvo scan ... --json findings.json`, then use **Open report** (or drop the file on the page). The file is parsed in
  the browser and never uploaded.

There is no backend, no authentication, and no network request at runtime.

## Compatibility with the mimvo package

The dashboard speaks the package's report format, so the two never disagree.

| | Package | Dashboard |
| --- | --- | --- |
| Report | `ScanReport` / `--json` (schema `2.0`) | `lib/report-io.ts` reads and writes the same layout. Schema `1.x` files from MemorySec still open. |
| Rules | `mimvo/rules.py` | `lib/rules.generated.ts`, generated by `scripts/sync-rules.py`: titles, severities, actions, OWASP, CWE, fix steps, messages. |
| Severity | `info` → `critical`, one step lower below 0.6 confidence | Same scale and the same rule in the demo data. |
| Actions | `action_plan()`: strongest action per record | **What to do** panel. |
| Counts | `flagged`, `flagged_pct`, `by_severity`, `by_rule`, `by_action` | `lib/report.ts`, same definitions (flagged counts distinct records). |
| Fingerprints | `sha256(code \x1f record_id)[:32]` | `lib/sha256.ts`, so exported demo reports carry real fingerprints. |
| Sources | `mimvo scan chroma\|qdrant\|pgvector\|pinecone\|langchain\|mem0\|jsonl` | `lib/catalog.ts`: the CLI flags and Python snippets shown in Integrations and New scan. |
| Incomplete scans | `errors`, `complete`, exit code 2 | Incomplete banner; a failed detector is never shown as a finding. |

**Export report** downloads the current scan as `--json` output; `ScanReport.model_validate_json` accepts it.

After changing rules in the package:

```bash
git clone https://github.com/jawadhussein462/mimvo ../mimvo   # once, next to this repo
npm run sync-rules        # runs scripts/sync-rules.py with the package's uv environment
```

## Getting started

```bash
npm install
npm run dev        # http://localhost:3000
npm run build && npm start
npm run typecheck
```

Requires Node 18.18+ (Node 20+ recommended).

Fonts (Archivo and IBM Plex Mono) are fetched by `next/font` **at build time** and self-hosted. The running site makes
no requests to Google. Builds therefore need network access once.

## Before you launch

- **Links.** `lib/site.ts` points at `github.com/jawadhussein462/mimvo`. Change it if the repository ends up elsewhere.
- **Demo requests.** `site.contactEmail` in `lib/site.ts` receives demo requests from `/demo`. Sending uses that
  Gmail account over SMTP, with `GMAIL_APP_PASSWORD` in `.env.local` (a Google app password, not the account
  password). Or set `site.demoBookingUrl` to a Cal.com / Calendly link to show a scheduling button instead of the form.
- **Docs.** `/docs` mirrors the package README (`components/docs/content.tsx`). Update both when the package changes.
- **OWASP mappings** come from the package (`ASI06`, `LLM01`, `LLM02`); edit them there and re-sync.
- **Social preview.** `app/opengraph-image.png` is used for link previews. Upload `public/brand/mimvo-social-dark.png`
  as the GitHub social preview too (Settings → General → Social preview).

## Stack

Next.js 15 (App Router), React 19, TypeScript (strict), Tailwind CSS 3.4, shadcn/ui on Radix primitives, Recharts,
Lucide, and Sonner for toasts.

Dependency floors are set at the December 2025 patched releases of Next.js and React. The app sets `nosniff`,
`X-Frame-Options: DENY`, `Referrer-Policy` and `Permissions-Policy` headers (`next.config.mjs`).

## Design notes

**Color carries meaning only.** The neutral palette has no brand hue. Color is reserved for risk state: critical,
high, medium, low, info and clean. The logo's flagged segment uses the high-severity color for the same reason.

**Severity never relies on color alone.** A four-bar meter shows the level by shape, and every badge also carries a
text label.

**Themes.** The landing page uses `.theme-light`. The dashboard, terminals and the privacy section use dark tokens.
Tokens are HSL triplets, so Tailwind alpha works (`bg-sev-critical/10`).

**Container queries.** The dashboard uses container queries (`@container/shell`, `@container/main`) instead of
viewport breakpoints, which lets the landing-page preview render the real dashboard components at desktop layout
inside a scaled frame.

**Motion.** The hero fades in on load and replays the CLI's real output; each section fades up once as it scrolls into
view (`components/landing/reveal.tsx`). Content is only hidden while JavaScript runs, and `prefers-reduced-motion`
shows everything at once.

## Product constraints the UI keeps

- **Read-only.** Delete, Quarantine and Review are always shown as *recommended* actions, never as executed ones.
- **No invented social proof.** No customer logos, metrics, testimonials, certifications or pricing.
- **No sign-in.** Neither the site nor the dashboard requires an account.
- **Local files stay local.** Opened reports are parsed in the browser and never uploaded.
- **Simulated scans.** The New scan flow runs entirely in the browser and says so; it shows the equivalent CLI command.

## Interactions

| Where | Behavior |
| --- | --- |
| Landing CTAs | **Book a demo** opens `/demo`; **Try open source** opens `/docs`; "Explore the demo report" opens `/dashboard#findings`. |
| Sidebar | Switches views and syncs the URL hash (`#overview`, `#scans`, `#findings`, `#integrations`). |
| Open report | Reads a `--json` report (button, menu, or drag and drop) and opens it as a scan. |
| Findings table | Search, severity filter, rule filter, pagination, keyboard-accessible rows. |
| Severity / rule panels | Clicking a severity or rule filters the table below. |
| What to do | Record ids under Delete, Quarantine and Review; clicking one filters the table to it. |
| Finding row | Opens the drawer: masked excerpt, detector scores, evidence, fix steps, OWASP and CWE links. |
| New scan | Choose a source, toggle checks, copy the equivalent command, watch the simulated run. |
| Integrations | Install-from-source lines, CLI and Python examples, and every flag for each source. |
| Export report | Downloads the scan in mimvo's JSON layout. |
